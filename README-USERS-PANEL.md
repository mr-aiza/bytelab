# حساب کاربری سایت بایت‌لب — راهنمای نصب

این پکیج یک سیستم کامل ثبت‌نام/ورود برای بازدیدکننده‌های سایت اضافه می‌کنه (نه ادمین):
کاربرها با **نام + شماره تماس + ایمیل + رمز عبور** ثبت‌نام می‌کنن، پروفایلشون رو از
`profile.html` ویرایش می‌کنن و می‌تونن نمونه‌کارهای صفحه‌ی `portfolio.html` رو با زدن آیکون
قلب به «علاقه‌مندی‌ها»ی خودشون اضافه کنن. یک پنل ساده (`users-admin.html`) هم برای خودت هست
تا لیست کاربرها رو ببینی و دسترسی هرکدوم رو فعال/غیرفعال کنی.

این سیستم کاملاً **جدا** از پنل مدیریت اصلی (`admin.html` / `bytelab-admin-worker.js`) کار
می‌کنه و روی KV Namespace جدید خودش می‌شینه؛ به داده‌های لیدها/بلاگ/نمونه‌کارهای فعلی دست
نمی‌زنه.

## فایل‌های این پکیج

| فایل | توضیح |
|---|---|
| `bytelab-users-worker.js` | کد کامل Worker حساب‌کاربری (ثبت‌نام/ورود/پروفایل/علاقه‌مندی/پنل کاربران) |
| `wrangler-users.toml` | تنظیمات دیپلوی این Worker |
| `account.html` | صفحه‌ی ورود/ثبت‌نام کاربر |
| `profile.html` | صفحه‌ی ویرایش پروفایل و رمز عبور |
| `favorites.html` | صفحه‌ی نمونه‌کارهای مورد علاقه‌ی کاربر |
| `users-admin.html` | پنل ساده برای خودت: لیست کاربرها + فعال/غیرفعال‌سازی دسترسی |
| `assets/bytelab-auth.js` | کتابخانه‌ی مشترک JS که همه‌ی صفحات بالا ازش استفاده می‌کنن |
| `portfolio.html` | (ویرایش‌شده) آیکون قلب به هر نمونه‌کار اضافه شده |
| `header.js` | (ویرایش‌شده) لینک «حساب کاربری» به منو اضافه شده |

## ۱) ساخت KV Namespace جدید

در Cloudflare Dashboard → Workers & Pages → KV، یک namespace جدید بساز، مثلاً با نام
`bytelab_users`. آیدیش رو کپی کن.

## ۲) ساخت Worker جدید

1. یک Worker جدید با نام `bytelab-users` بساز (یا با `wrangler deploy -c wrangler-users.toml`
   دیپلویش کن).
2. کد `bytelab-users-worker.js` رو در آن قرار بده.
3. در تنظیمات Worker → Settings → Bindings → KV Namespace Bindings، متغیر `USERS_KV` رو به
   namespace ای که تو مرحله‌ی ۱ ساختی وصل کن (یا `id` را در `wrangler-users.toml` بگذار).

## ۳) متغیر محیطی (Secret)

از Settings → Variables and Secrets این Worker، مقدار زیر رو به‌صورت **Secret** اضافه کن:

- `ADMIN_PANEL_PASSWORD` — رمز عبور ورود به `users-admin.html` (یک رمز قوی و متفاوت از
  رمزهای دیگه انتخاب کن)

اختیاری (Variable عادی):
- `USERS_SESSION_HOURS` — مدت اعتبار نشست کاربر عادی، به ساعت (پیش‌فرض ۷۲۰ = ۳۰ روز)
- `ADMIN_ALLOWED_ORIGIN` — دامنه‌ی مجاز CORS (پیش‌فرض `*`؛ بهتره دامنه‌ی سایتت رو بگذاری،
  مثلاً `https://bytelabpro.xyz`)

## ۴) وصل کردن صفحات به Worker جدید

بعد از دیپلوی، آدرس واقعی Worker (چیزی شبیه `https://bytelab-users.YOUR_SUBDOMAIN.workers.dev`)
رو جای `API_URL` در **دو فایل** جایگزین کن:

- `assets/bytelab-auth.js` (خط بالای فایل)
- `users-admin.html` (داخل تگ `<script>` پایین فایل)

## ۵) آپلود فایل‌ها

فایل‌های زیر رو در کنار بقیه‌ی فایل‌های سایتت (همون جایی که `index.html` و `portfolio.html`
هست) آپلود/جایگزین کن:

- `account.html`, `profile.html`, `favorites.html`, `users-admin.html`
- `assets/bytelab-auth.js`
- `portfolio.html` (نسخه‌ی جدید، آیکون قلب داره)
- `header.js` (نسخه‌ی جدید، لینک حساب کاربری داره)

## ۶) تست

1. `account.html` رو باز کن، یک حساب تستی بساز.
2. وارد `profile.html` شو و نام/ایمیل رو ذخیره کن.
3. برو `portfolio.html`، روی آیکون قلب یک نمونه‌کار بزن؛ باید تو `favorites.html` دیده بشه.
4. `users-admin.html` رو باز کن، با `ADMIN_PANEL_PASSWORD` وارد شو؛ باید همون کاربر تستی رو
   با تعداد علاقه‌مندی‌هاش ببینی. با دکمه‌ی «مسدود کردن» می‌تونی دسترسی ورودش رو قطع کنی.

## نکات امنیتی

- رمزهای کاربرها هرگز خام ذخیره نمی‌شن؛ فقط هش (SHA-256 + نمک تصادفی) در KV نگه‌داری می‌شه —
  دقیقاً همون روشی که در ریحون گلد گالری استفاده شده.
- تلاش‌های ناموفق ورود (هم کاربر عادی، هم پنل ادمین) محدود شده: بعد از ۵ بار اشتباه، ۱۵ دقیقه
  قفل موقت اعمال می‌شه.
- توصیه می‌شه `ADMIN_ALLOWED_ORIGIN` رو روی دامنه‌ی واقعی سایتت تنظیم کنی.
- کاربر مسدودشده («غیرفعال») نمی‌تونه وارد بشه، ولی نشست‌های از قبل بازش (اگه توکن معتبر
  داشته باشه) تا انقضای طبیعی همچنان کار می‌کنن؛ برای قطع فوری، از پنل ادمین کاربر رو مسدود
  کن و در صورت نیاز از KV هم `session:` مربوطه رو پاک کن.
